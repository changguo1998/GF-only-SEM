# 全流程性能与容量测试

## 测试目的

识别 preprocess、forward、record I/O 和 postprocess 的主要耗时，评估磁盘吞吐、主机
内存和 GPU 显存对可计算网格的限制，并验证 Debug 性能输出不会进入 Release。

## 测试方法

Debug 构建分别用 `GF_PRE_PROFILE=1`、`GF_FORWARD_PROFILE=1` 和后处理 profile 输出
阶段秒数及百分比。20³ 用于可重复的后处理瓶颈分析；28³/40³ 用于容量上限和实际 I/O
缩放。所有 HDF5 保持不压缩。

## 参数选择

- 20³ fullspace：800 步、16 tiles、MPI-4，比较优化前后。
- 28³：作为约定最大常规研究网格；64 GiB 后处理限制。
- 40³ Debug：64000 单元、160 全域四字段快照、约 226 GB wavefields。
- 后处理字段预算默认 32 GiB，可用 `GF_POST_MEMORY_GB` 覆盖；预算不是物理内存探测值。

## 测试结论

- 20³ 后处理优化空间主要来自重复 record 读取；重用后总时长 34.3→19.0 s，HDF5 读取
  占比 59.187%→17.693%，继续完全消除读取也不可能消除计算与写出成本。
- 28³ 后处理峰值约 40.2 GiB（3 workers）；32³ 估算约 89 GiB，因此 28³ 被设为当前
  常规五网格研究上限，而非求解器硬上限。
- 40³ 能在 16 GB RTX 5060 Ti 上完成计算，GPU 显存容纳求解状态；真正瓶颈是 Debug
  全域 record 的磁盘写入和后处理内存/I/O。
- 40³ 三方向墙钟随磁盘压力增长为 307.1/446.1/610.1 s；MPI-2 后处理 2346.7 s。
- 预处理/正演 profile 的历史逐阶段百分比没有保存在仓库中，不能从会话文字恢复精确值；
  当前保留了可重复的编译期 Debug 计时入口。Release 不编译这些 profile/详细日志分支。
